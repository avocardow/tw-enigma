# @tw-enigma/scramble v1 - Product Requirements Document

## Overview

The `@tw-enigma/scramble` package is a proprietary, client-side JavaScript module that provides a dynamic "hacker" visual effect for websites using the tw-enigma CSS optimization tool. This v1 release is an **internal, unlicensed, and private** package designed to prove technical viability and gather internal feedback.

### Problem Statement
While tw-enigma successfully optimizes CSS by generating short, mangled class names, these optimized class names are only visible to developers who inspect the source code. There is an opportunity to create a compelling, aesthetic feature that showcases this optimization in a visually engaging way.

### Solution
A client-side script that continuously scrambles tw-enigma's optimized class names in both the DOM and CSS rules simultaneously, creating a "digital rain" or "hacker terminal" effect visible in browser developer tools. This provides a unique, memorable demonstration of the optimization tool's capabilities.

### Target Audience
- Internal development team (v1 primary audience)
- Developers who have adopted tw-enigma and want to add dynamic flair to projects
- Personal portfolios, agency websites, and themed marketing sites seeking creative expression

### Value Proposition
- **Purely Aesthetic**: Provides creative expression and memorable user experience
- **Zero Functional Impact**: Maintains perfect visual styling while creating effect
- **Technical Showcase**: Demonstrates sophisticated DOM/CSSOM synchronization
- **Performance Optimized**: Mandates requestAnimationFrame for optimal rendering performance, battery efficiency, and alignment with browser repaint cycles

## Core Features

### 1. Continuous Class Scrambling
**What it does**: Continuously randomizes class attributes of elements styled by tw-enigma while simultaneously updating corresponding CSS rules.

**Why it's important**: Creates the core "hacker effect" that makes the optimization visible and engaging.

**How it works**: Uses a synchronized update system that modifies CSS selectors in stylesheets and DOM element classes in the same animation frame to prevent visual flicker.

### 2. Perfect Visual Consistency
**What it does**: Ensures that all visual styling (colors, layout, fonts, spacing) remains completely unchanged during scrambling.

**Why it's important**: The effect must be purely aesthetic - any visual disruption would break user experience.

**How it works**: Maintains live references to CSS rules and DOM elements, updating only selectors/class names while preserving all style properties.

### 3. Configurable Speed Control
**What it does**: Allows developers to control the scrambling interval via CLI flags.

**Why it's important**: Different projects may want subtle flickering versus rapid chaotic effects.

**How it works**: CLI injects speed settings directly into the script at build time, eliminating runtime configuration overhead.

### 4. Accessibility Compliance
**What it does**: Automatically disables the scrambling effect for users with motion sensitivity.

**Why it's important**: Respects user accessibility preferences and ensures inclusive experience.

**How it works**: Checks `prefers-reduced-motion` media query on initialization and exits immediately if motion should be reduced.

### 5. Graceful Error Handling
**What it does**: Continues operating even when encountering inaccessible cross-origin stylesheets or other edge cases.

**Why it's important**: Third-party resources (Google Fonts, analytics) shouldn't break the effect.

**How it works**: Uses try-catch blocks around stylesheet access and individual class updates.

## Technical Architecture

### System Components

#### 1. Private Package Structure
```
packages-private/scramble/
├── src/
│   └── index.ts              # Main scramble logic
├── dist/
│   └── scramble.min.js       # Built IIFE output
├── package.json              # Private package configuration
└── tsup.config.ts           # Build configuration
```

#### 2. CLI Integration Layer
- **Detection Logic**: CLI scans for `--scramble` flags across all commands
- **Package Resolution**: Attempts to resolve private package using ESM-compatible imports
- **Build Orchestration**: Builds scramble package with injected configuration when flags present
- **HTML Discovery**: Recursively scans build output directory for HTML files (*.html)
- **Script Injection**: Copies scramble script and injects `<script>` tag before `</body>`
- **Timing Coordination**: Ensures CSS generation completes before scramble script injection

#### 3. Client-Side Runtime Engine
- **Discovery Phase**: Scans stylesheets using regex `^\.[a-z][a-z0-9]*$` to identify tw-enigma classes
- **Mapping Phase**: Creates registry linking CSS rules to DOM elements
- **Animation Loop**: Uses requestAnimationFrame for synchronized updates

### Data Models

#### Class Registry Structure
```typescript
Map<string, {
  cssRule: CSSStyleRule,    // Live reference to CSS rule
  elements: Element[]       // Array of DOM elements using this class
}>
```

#### Configuration Schema
```typescript
interface ScrambleConfig {
  SCRAMBLE_INTERVAL: number;     // Milliseconds between updates (50-1000ms)
  SCRAMBLE_MODE: "all";          // Update mode (v1: all chars at once)
  CHARSET: string;               // Character set for random generation
  DEBUG_MODE: boolean;           // Console logging enabled
  RETRY_ATTEMPTS: number;        // CSS loading retry attempts (default: 3)
  CLEANUP_INTERVAL: number;      // Registry cleanup interval in seconds (default: 30)
  MAX_REGISTRY_SIZE: number;     // Maximum classes to track (default: 1000)
  PERFORMANCE_MONITORING: boolean; // Track performance metrics in debug mode
}
```

#### Security Considerations
```typescript
interface SecurityConfig {
  CSP_COMPLIANCE: boolean;       // Use nonce for script injection if CSP detected
  ORIGIN_VALIDATION: boolean;    // Validate stylesheet origins before access
  IFRAME_DETECTION: boolean;     // Disable in cross-origin iframes
  SOURCE_MAP_SAFE: boolean;      // Preserve source map functionality
}
```

## Integration Contract with `@tw-enigma/cli`

This section defines the mandatory responsibilities of the core CLI when the `--scramble` flag is used.

### CLI Package Discovery Requirements
The CLI must implement the following discovery logic when any `--scramble*` flag is detected:

```typescript
// CLI Integration Logic
try {
  // 1. Attempt to resolve scramble package path
  const scramblePackagePath = require.resolve('@tw-enigma/scramble/dist/scramble.min.js');

  // 2. If successful, proceed with scramble integration
  await integrateScrambleEffect(scramblePackagePath, scrambleOptions);

} catch (error) {
  // 3. If package not found, show warning and continue without scramble
  console.warn('⚠️ Scramble effect requires @tw-enigma/scramble package, which was not found. Skipping scramble integration.');
  // Continue normal CLI operation without scramble
}
```

### CLI Asset Management Responsibilities

#### 1. Package Discovery
- **MUST** verify `@tw-enigma/scramble` package is installed using `require.resolve()` or equivalent
- **MUST** gracefully continue CLI operation if package is not found
- **MUST** display clear warning message when package unavailable

#### 2. Build Orchestration
- **MUST** build scramble package automatically when scramble flags detected
- **MUST** inject user configuration into scramble template before building
- **MUST** ensure scramble build completes before HTML injection phase

#### 3. Asset Copying
- **MUST** copy final `scramble.min.js` from scramble package's `dist/` folder
- **MUST** place script in user's build output directory (e.g., `dist/assets/enigma-scramble.js`)
- **MUST** preserve script integrity and minification

#### 4. HTML Injection
- **MUST** scan build output directory for HTML files using glob pattern `**/*.html`
- **MUST** inject `<script>` tag before closing `</body>` tag in each HTML file
- **MUST** ensure script loads after all CSS to prevent race conditions

#### 5. Configuration Passing
- **MUST** pass scramble configuration via build-time template injection
- **MUST NOT** use runtime configuration methods (data attributes, global variables)
- **MUST** validate configuration values (speed limits, character sets)

### Integration Sequence
```bash
# User Command
enigma css-config --preset production --scramble --scramble-speed=100 --scramble-debug

# CLI Internal Sequence
1. Parse CLI flags and extract scramble configuration
2. Attempt package discovery (@tw-enigma/scramble)
3. If found: Build scramble with injected configuration
4. Execute normal CSS processing (css-config)
5. Copy scramble script to build output
6. Scan for HTML files in output directory
7. Inject script tags into discovered HTML files
8. Display success message with scramble configuration summary
```

### Error Handling Contract
- **Package Not Found**: Warn and continue without scramble (non-blocking)
- **Build Failure**: Warn and continue without scramble (non-blocking)
- **HTML Injection Failure**: Warn but complete other CLI operations (non-blocking)
- **Configuration Validation**: Error and exit if invalid scramble settings provided (blocking)

## Risks and Mitigations

### Technical Challenges

#### Risk: CSS Rule Modification Failures
**Description**: Browser security restrictions or stylesheet access issues could prevent CSS rule updates.

**Likelihood**: Medium - Cross-origin stylesheets are common

**Impact**: High - Would break scrambling effect entirely

**Mitigation**:
- Implement robust try-catch blocks around all CSSOM operations
- Gracefully skip inaccessible stylesheets
- Continue operation with accessible rules only
- Provide debug logging to identify problematic stylesheets

#### Risk: Timing/Race Conditions
**Description**: Script may initialize before tw-enigma CSS is fully loaded, resulting in empty registry.

**Likelihood**: High - CSS loading is asynchronous

**Impact**: High - No scrambling effect despite successful setup

**Mitigation**:
- Implement CSS loading detection with retry mechanism
- Use MutationObserver to detect stylesheet additions
- Add fallback polling mechanism for CSS rule discovery
- Provide initialization status logging in debug mode

#### Risk: Memory Leaks from DOM References
**Description**: Element references in registry may prevent garbage collection when elements are removed.

**Likelihood**: Medium - Dynamic content changes are common

**Impact**: Medium - Gradual memory consumption increase

**Mitigation**:
- Implement periodic registry cleanup (every 30 seconds)
- Check element.isConnected before each scramble iteration
- Remove disconnected elements from registry automatically
- Monitor memory usage in debug mode

#### Risk: Performance Degradation
**Description**: Continuous DOM/CSS updates could impact page performance or battery life.

**Likelihood**: Low - Optimized implementation planned

**Impact**: High - Would violate "zero functional impact" requirement

**Mitigation**:
- Use requestAnimationFrame for optimal timing
- Implement efficient registry with minimal object creation
- Profile performance with large CSS files
- Add performance monitoring in debug mode

#### Risk: Browser Compatibility Issues
**Description**: Different browsers may handle CSSOM manipulation differently.

**Likelihood**: Medium - Browser APIs can vary

**Impact**: Medium - Effect might not work on some browsers

**Mitigation**:
- Target modern evergreen browsers only for v1
- Test across Chrome, Firefox, Safari, Edge
- Implement feature detection before running scramble logic
- Graceful degradation when APIs unavailable

### MVP and Scope Challenges

#### Risk: Feature Scope Creep
**Description**: Temptation to add advanced features like MutationObserver, complex animations, or licensing system.

**Likelihood**: High - Natural developer tendency

**Impact**: Medium - Could delay v1 delivery

**Mitigation**:
- Explicitly document v1 scope limitations in PRD
- Defer all advanced features to future versions

- Regular scope review meetings

#### Risk: Monorepo Integration Complexity

**Impact**: Medium - Could complicate development workflow

**Mitigation**:

- Implement graceful fallback when package unavailable
- Test both scenarios: with and without private package

### Resource Constraints

**Impact**: Medium - Could miss edge cases

**Mitigation**:

### Technical Specifications

#### CSS Selector Detection Regex
```
Pattern: ^\.[a-z][a-z0-9]*$
Explanation:
- ^\.     : Starts with literal dot
- [a-z]   : First character must be lowercase letter
- [a-z0-9]*: Subsequent characters are lowercase letters or numbers (zero or more)
- $       : End of string
```

#### Supported Class Name Examples
```
✅ Supported: .a, .ab, .abc, .x1, .hello, .a2b3c4
❌ Not Supported: .1abc (starts with number), .ABC (uppercase), .a-b (hyphen)
```

#### Performance Requirements
- **Animation Frame Budget**: <1ms per scramble iteration (measured via performance.now())
- **Memory Overhead**: <100KB for class registry (measured via performance.measureUserAgentSpecificMemory when available)
- **CPU Usage**: <1% average CPU utilization (measured via CPU profiling)
- **Bundle Size**: <10KB minified script size
- **Initialization Time**: <50ms from DOMContentLoaded to first scramble
- **Registry Limits**: Maximum 1000 tracked classes, 10000 total DOM elements
- **Battery Impact**: Negligible battery drain (same as 60fps CSS animation)
- **Lighthouse Score**: Zero impact on Performance, Accessibility, Best Practices scores

### Research Findings

1. **Server-Side Scrambling**: Rejected due to complexity and inability to create dynamic effect
2. **CSS Animation-Based**: Rejected due to inability to change actual class names

4. **WebWorker Implementation**: Rejected due to DOM access requirements

#### Browser API Compatibility Research
- **CSSStyleRule.selectorText**: Supported across all target browsers, writable
- **Element.classList.replace()**: Supported in all modern browsers
- **requestAnimationFrame**: Universal support, optimal for visual updates
- **prefers-reduced-motion**: Supported in all target browsers
