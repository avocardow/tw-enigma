# Title: Create comprehensive test fixtures
# Status: pending
# Dependencies: 13
# Priority: low
# Description: Create a set of test fixtures covering various scenarios to validate the scramble effect.
# Details:
Create test fixtures for the following scenarios:

1. **Static HTML with external CSS**
   - Create a simple HTML page with external CSS file
   - Include various tw-enigma generated classes
   - Test with both simple and complex selectors

2. **React SPA with CSS-in-JS**
   - Create a simple React app using styled-components
   - Configure tw-enigma to process the CSS
   - Test with dynamic content updates

3. **Vue SPA with scoped CSS**
   - Create a simple Vue app with scoped CSS
   - Configure tw-enigma to process the CSS
   - Test with component transitions

4. **Next.js SSR with mixed CSS approaches**
   - Create a simple Next.js app with various CSS approaches
   - Configure tw-enigma to process the CSS
   - Test with server-rendered and client-rendered content

5. **Edge case: Large number of classes**
   - Create a page with 1000+ CSS classes
   - Test performance and memory usage

6. **Edge case: Third-party CSS**
   - Create a page with Bootstrap, Material-UI, or other third-party CSS
   - Test handling of cross-origin stylesheets

Each fixture should include:
- Source code in `packages/cli/tests/fixtures/`
- Build configuration for tw-enigma
- Test script to build and validate the fixture
- Documentation of expected behavior

Example test script for a fixture:

```bash
#!/bin/bash

# Build the fixture
cd packages/cli/tests/fixtures/static-html
pnpm build

# Validate the build output
if [ ! -f "dist/assets/enigma-scramble.js" ]; then
  echo "❌ Scramble script not found in build output"
  exit 1
fi

# Check HTML injection
if ! grep -q "enigma-scramble.js" "dist/index.html"; then
  echo "❌ Scramble script not injected into HTML"
  exit 1
fi

echo "✅ Fixture validation passed"
```

# Test Strategy:
Run each test fixture and manually verify the scramble effect in the browser. Check that the effect works correctly in all scenarios and gracefully handles edge cases. Verify that the effect respects accessibility preferences and doesn't impact page performance.
