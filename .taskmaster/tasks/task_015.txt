Example README.md structure:

```markdown
# @tw-enigma/scramble

> Internal package for creating a "hacker" visual effect with tw-enigma CSS classes.

## Development Setup

1. Clone the tw-enigma monorepo
2. Create `packages-private` directory (locally only)
3. Add `packages-private/*` to `pnpm-workspace.yaml` (DO NOT COMMIT)
4. Install dependencies with `pnpm install`
5. Build the package with `pnpm --filter @tw-enigma/scramble build`

## Architecture Overview

The scramble effect works by:

1. Scanning stylesheets for tw-enigma generated class selectors
2. Building a registry mapping CSS rules to DOM elements
3. Continuously scrambling class names using requestAnimationFrame
4. Synchronizing updates to both CSS rules and DOM elements

## Key Design Decisions

- **requestAnimationFrame**: Used for optimal performance and battery efficiency
- **Registry Structure**: Maps class names to both CSS rules and DOM elements for synchronized updates
- **Error Handling**: Gracefully handles cross-origin stylesheets and other edge cases
- **Accessibility**: Automatically respects prefers-reduced-motion preference

## CLI Integration

The scramble package is integrated with the tw-enigma CLI via the following flags:

- `--scramble`: Enable the scramble effect
- `--scramble-speed=<ms>`: Set the scramble interval (50-1000ms)
- `--scramble-debug`: Enable debug logging

Example usage:

```bash
enigma css-config --preset production --scramble --scramble-speed=100
```

## Debugging

Enable debug mode with the `--scramble-debug` flag to see detailed logging in the browser console.

Common issues:
- No scrambling effect: Check if tw-enigma classes are present and accessible
- Cross-origin stylesheet errors: These are expected and handled gracefully
- Performance issues: Try increasing the scramble interval
```
